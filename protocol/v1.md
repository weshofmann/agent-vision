# AVCP v1

This is the language-neutral contract shared by the Go core and C++ presentation.
The approved architecture is in
[the design](../docs/superpowers/specs/2026-09-26-go-core-architecture-design.md),
sections 5 and 10. v1 is connection-scoped, frontend-spawned, and has no listener,
attach, reconnect, persistence, arbitrary exec options or native wait-status ABI.

All integers are unsigned big-endian. A frame consists of exactly a 32-byte
header followed by the stated body bytes; there is no padding or checksum.

| Offset | Bytes | Field |
| --- | --- | --- |
| 0 | 4 | ASCII `AVCP` (`41 56 43 50`) |
| 4 | 2 | Major version: 0 handshake (including its Error), 1 negotiated |
| 6 | 2 | Message type, 1–14 |
| 8 | 2 | Flags, zero |
| 10 | 2 | Reserved, zero |
| 12 | 4 | Body length, at most 65,536 |
| 16 | 8 | Request ID |
| 24 | 8 | Session ID |

Unknown type/version, nonzero flags/reserved, invalid direction, malformed exact
schema or request IDs are fatal. Validate the header before body allocation.
Read exactly each frame; fragmentation and coalescing do not alter boundaries.
Short I/O and EINTR advance/retry the current operation; zero progress fails.
EOF before any header byte is clean contact loss; EOF at any later position is
truncation. Never resynchronize or continue after a partially written frame.
The connection owns a 2-second first-byte partial-frame deadline; generic codecs
accept `io.Reader`/`io.Writer` and impose no idle-connection timeout.

Terminal bytes are arbitrary, including `00`, `ff` and ESC. Text strings are u16
byte-length-prefixed UTF-8 with no NUL. Every schema consumes the entire body.
Dimensions are 1–4096. F means frontend and B means backend.

| Type | Name | Direction | Exact body | Header IDs |
| --- | --- | --- | --- | --- |
| 1 | Hello | F→B | u16 minMajor, u16 maxMajor | request nonzero, session 0, version 0 |
| 2 | HelloAck | B→F | u16 selectedMajor, u32 maxPayload, u32 capabilities, 16 epoch bytes | Hello request, session 0, version 0 |
| 3 | CreateSession | F→B | u16 rows, u16 cols, u32 receiveWindow | request nonzero, session 0 |
| 4 | SessionCreated | B→F | u16 rows, u16 cols, u32 acceptedWindow | Create request, assigned nonzero session |
| 5 | InputBytes | F→B | 1–32,768 raw bytes | request/session nonzero |
| 6 | ResizeSession | F→B | u16 rows, u16 cols | request/session nonzero |
| 7 | CloseSession | F→B | empty | request/session nonzero |
| 8 | Shutdown | F→B | empty | request nonzero, session 0 |
| 9 | OutputBytes | B→F | u64 sequence, 1–32,768 raw bytes | request 0, session nonzero |
| 10 | SessionExited | B→F | u8 kind, u32 value, u8 coreDump, u64 lastOutputSequence, u8 drainReason | request 0, session nonzero |
| 11 | SessionClosed | B→F | u64 lastOutputSequence | Close request or 0 async, session nonzero |
| 12 | Error | B→F | u16 code, u32 partialInputBytes, u16 messageBytes, UTF-8 message | causing request or 0 async, related session or 0 |
| 13 | Ack | B→F | u16 completedType | request nonzero; session nonzero except Shutdown |
| 14 | OutputCredit | F→B | u32 returned raw bytes | request/session nonzero |

Hello initially offers [1,1]; lack of overlap produces VERSION and closes.
The structural decoder accepts an ordered u16 version range, including zero; negotiation and
duplicate/pre-handshake traffic checks belong to the connection. HelloAck selects
1, advertises maxPayload 65,536, capabilities 0 and a random 16-byte backend epoch.
Create/Created windows are exactly 262,144 bytes. Ack completedType is Input(5),
Resize(6), Shutdown(8) or Credit(14); it means complete PTY write, applied ioctl,
complete owned cleanup or validated accounting respectively.

Exit kinds: exit=1 (value 0–255), signal=2 (nonzero platform signal number),
unavailable=3 (value 0). coreDump is 0 or 1 and can be 1 only for signal.
Signal values are not a cross-platform signal ABI. Drain reasons are EOF=1,
no-data=2, byte-cap=3, time-cap=4, credit-cap=5, I/O-error=6, explicit-close=7.
Caps/errors/close indicate possible unread tail loss; even EOF makes no descendant
supervision promise. lastOutputSequence may be zero when no output was admitted;
Output sequence starts at 1 and strictly increments in session state.

Error message length is at most 1,024 bytes. partialInputBytes is the exact written
prefix of a failed Input (0 before first write, at most 32,768); retry is not
implicit. Error codes are:

| Code | Name |
| --- | --- |
| 1 | VERSION |
| 2 | PROTOCOL |
| 3 | UNKNOWN_SESSION |
| 4 | STATE |
| 5 | LIMIT |
| 6 | SPAWN |
| 7 | PTY_IO |
| 8 | INPUT_TIMEOUT |
| 9 | RESIZE |
| 10 | STATUS_UNAVAILABLE |
| 11 | INTERNAL |

Schema decoding and state validation are separate. Every u32 Credit is structurally
representable; zero, over-return, duplicate or unsent credit is rejected by
accounting with a correlated STATE error on usable contact. Credit excludes all
framing/sequence overhead. Unknown/released sessions return UNKNOWN_SESSION,
including repeat Close. Neither is a decoder failure.

Frontend request IDs are nonzero and strictly increasing, never reused; wrap fails
contact. `RequestIDs.Accept` enforces a constant-storage watermark at the serialized
admission boundary. Response correlation and outstanding lanes are connection
state: 48 ordinary (Hello/Create/Input/Resize), 16 Credit, 16 Close and 1 Shutdown.
Every accepted request has one terminal response on usable contact; different
sessions may complete out of order. Async events have request 0. Session IDs are
opaque nonzero u64, never reused in the backend epoch; neither IDs nor epochs encode
PIDs or addresses. Created precedes public session events. All successfully
admitted/in-flight output precedes seal/Exited; none follows Exited/Closed.
Contact loss never manufactures exact exit status.

v1 resource bounds: 16 sessions including Starting; exactly 256 KiB output/session,
4 MiB aggregate raw output, 128 KiB control reserve, 64 KiB queued input/session,
and at most 32,768 raw bytes per Input/Output. Ordinary saturation cannot consume
reserved control lanes. Allocation/metadata overhead is separately bounded.
`policy.MaxOutputChunks=128` includes in-flight chunks and is a local policy cap,
not another advertised wire window.

Named initial implementation policy in `core/internal/policy`: 64 KiB/100 ms drain;
2 s handshake, partial-frame, write/credit no-progress and backend cleanup;
1 s input; 100 ms credit flush/worker join target; 250 ms signal grace;
1 s frontend post-KILL reap observation. Timing/drain tuning with evidence may
preserve v1 observable bounded-drain/error/seal semantics; schema/resource changes
require compatible negotiated semantics. Frontend shutdown uses the same initial
2 s watchdog. No deadline is implemented by the standalone wire codec.

`tests/protocol/v1/*.hex` contains literal complete frames with whitespace-separated
hex only. Go tests decode and encode these bytes independently; C++ tests reuse
them. `frame_max.hex` is a valid maximum framing body but an invalid Input schema,
while `input_max.hex` and `output_max.hex` are valid maximum data messages. Fixtures
use synthetic IDs/text and contain no live process/environment data.
